# SOURCES — What Is a Game Design Document?

## Source material (supplied by Bear, 2026-09-18)

1. Transcript one: a YouTube tutorial on whether and how to make a game design document (the creator sells a "How to Code in Unity" course; the video's own chapters: why you would need one, how to make one, picking a format, the one-page method). Claims used: the one reason (explain the game to someone else, often you); ideas change; keep it in your head only if the game is small enough; start with core concept and pillars, up to four or five; mechanics and controls next; look, sound, story, timeline as needed; the house-and-builder format argument; the one-page method after Stone Librande's GDC talk.
2. Transcript two: a studio presentation on game design documents using the presenters' own roguelike as the example (chapters: what is a GDD, when to use it, why bother, storage, freezing at production, then a section-by-section walkthrough). Claims used: the Wikipedia definition; outline not pitch; risk management, alignment, scope and feature creep; storage from shared doc to wiki or tool with version control; freeze the document at production, change control, "measure twice, cut once".
3. Worked example: walker-jumpman-clawd/design/GDD.md 0.3.0-draft (sha256 438eff052361f67671a918775a00283587e642552c8cc15d59345e7cf6c2b066), design/decisions.md, design/CHANGELOG.md, godot/features/player/tuning.gd at commit 382f2ba.

## Verified on the web (2026-09-18)

- Stone Librande, "One-Page Designs", GDC 2010 (GDC Vault; stonetronix.com/gdc-2010/OnePageDesigns.ppt). Narrated as "twenty-ten".
- Wikipedia, "Game design document": "a highly descriptive living software design document of the design for a video game"; the "living document" sense as changing when limits and new abilities are discovered. Narrated as "the standard definition".
